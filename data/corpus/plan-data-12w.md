# 学习计划：数据开发（数仓 / ETL）方向 · 12 周

> 目标：6 个月内具备投「数据开发工程师 / 大数据开发 / 数仓工程师 / ETL 工程师（1 年左右经验）」的能力，深圳为主。
> 你的起点：数据科学与大数据技术本科（2026 届）、Java + Spring Boot 两个项目、会基础 SQL、会一点 Python。
> 时间假设：**每天 4–6 小时、每周 6 天**，12 周 ≈ 390 小时。每天只有 2–3 小时的话，所有周数 × 1.8。

---

## 一、先看清目标岗位到底要什么

深圳「数据开发」类 JD 的高频要求（按出现频率排）：

| 要求 | 出现频率 | 说明 |
|---|---|---|
| **SQL 熟练**（复杂查询、窗口函数、调优） | 几乎 100% | 这是命根子，笔试第一关就是手写 SQL |
| **Hive / Spark** | 90% | 离线数仓主力 |
| **数仓分层与维度建模**（ODS/DWD/DWS/ADS、星型模型） | 85% | 面试必问，且要能画图讲 |
| **调度工具**（DolphinScheduler / Airflow / Azkaban） | 70% | 会配 DAG、懂依赖与重跑 |
| **Flink / Kafka**（实时） | 60% | 加分项，会基础就能打赢一半候选人 |
| **OLAP 引擎**（Doris / ClickHouse / StarRocks） | 55% | 深圳电商、金融公司常用 |
| **Python / Shell 脚本** | 60% | 写 ETL 脚本、调接口 |
| **数据质量与治理** | 40% | 空值监控、口径统一、血缘 |

**关键认知**：这个岗位不考你 JVM 和 AQS，考的是**"你能不能用 SQL 和组件把数据从源头搬到看板上，并且不出错"**。

## 二、为什么这条路适合你（也说清代价）

**优势**
1. **专业对口**：数据科学与大数据技术，课程里的数据库原理、大数据处理基础直接能用，面试时"科班"标签是加分
2. **竞争小**：Java 后端一个岗位几百份简历，数据开发常常几十份
3. **退路宽**：做 2–3 年可以转数据架构、指标平台、也可以转算法/数据科学（有数仓底子转算法比纯后端转容易）
4. **不看八股**：不考 JVM、不考 AQS，考 SQL 和建模，**投入产出比高**
5. **AI 时代更稳**：模型要吃数据，数据管道是刚需

**代价（必须接受）**
1. **要搭环境**：Hadoop 生态在本机搭起来比 Spring Boot 麻烦（下面给了三条降级方案）
2. **SQL 要练到手熟**：不是"会写"，是"看到业务问题 3 分钟内能写出窗口函数"
3. **起薪不比 Java 高**：深圳 1 年经验 10–15K，和 Java 持平，但天花板更高
4. **岗位绝对数量少于 Java**：所以简历和项目必须精准对口

## 四、环境准备（第 0 周解决，别拖）

按"从轻到重"三条路，**任选一条，能跑通就行**：

**方案 1（推荐，最省事）：Docker Desktop + 现成镜像**
- 装 Docker Desktop（Windows）
- `docker run -d -p 10000:10000 -p 10002:10002 --name hive apache/hive:4.0.0`（HiveServer2 + WebUI）
- Spark 用本地模式：下载 Spark 3.5 解压，`spark-sql` 直接跑，元数据用内置 Derby
- 优点：半小时搞完；缺点：单机，学不到集群运维（但面试也不考你运维）

**方案 2（最贴近生产）：云服务器**
- 阿里云/腾讯云学生机（2C4G，几十块/月），装 Hadoop + Hive + Spark 伪分布式
- 优点：真实 Linux 环境，能练 Shell、能练调度；缺点：要花点钱和半天时间

**方案 3（零成本起步）：先不装集群**
- 用 **DuckDB**（单文件、支持窗口函数）+ **MySQL** 练 SQL 和建模
- 学到 Hive 那周再上 Docker
- 优点：立刻能开始；缺点：Hive 语法差异要后期补

> 建议：**方案 3 起步 → 第 5 周切方案 1**。别在装环境上耗一周，那是新手最大的时间黑洞。

## 五、12 周主计划

### 第 0 周：地基（约 25 小时）

**学什么**
- Linux 与 Shell（8h）：`grep/awk/sed/sort/uniq/cut`、`crontab`、`nohup`、文件权限、`top/df/free`、写一个"统计日志里 TOP10 IP"的脚本
- Git（4h）：分支、PR、`.gitignore`、README
- Python 基础补强（8h）：文件读写、`requests`、`pandas` 基础（read_csv/groupby/merge/to_sql）、`sqlalchemy` 连 MySQL
- 数据库环境（5h）：MySQL 8 装好（Docker 或本地），导入一份公开数据集（下面项目 A 用）

**怎么学**：Shell 不要背命令表，**每天挑一个真实任务用 Shell 做一遍**（比如统计日志、批量重命名）。

**产出**：一个能跑的 MySQL 实例 + 一个把 CSV 导入 MySQL 的 Python 脚本。

---

### 第 1–2 周：SQL 深水区（约 60 小时）★ 全程最重要

**学什么**
1. **基础巩固**（8h）：JOIN 五种、子查询、UNION、CASE WHEN、NULL 陷阱（`!= NULL` 永远不成立）
2. **窗口函数**（20h，重中之重）
   - `ROW_NUMBER / RANK / DENSE_RANK`、`LAG / LEAD`、`SUM/AVG OVER (PARTITION BY … ORDER BY …)`
   - 典型题：每部门 Top3 薪资、连续 3 天登录、同比环比、累计求和、留存率
3. **复杂查询模式**（16h）
   - 行列转换（`CASE WHEN + 聚合`、`PIVOT`）
   - 漏斗分析、留存分析、复购率、GMV 拆解
   - 去重取最新一条（`ROW_NUMBER` 或 `GROUP BY + MAX`）
4. **性能与执行计划**（10h）：`EXPLAIN` 字段、索引失效、深分页优化、大表 JOIN 顺序
5. **刷题**（6h）：牛客 SQL 篇（1–60 题）+ LeetCode 数据库（简单+中等 30 题）

**怎么学**：**先自己想 5 分钟，再看答案**；每道题写完用 `EXPLAIN` 看一下走了什么索引。窗口函数必须练到手能默写。

**产出**：一份《SQL 题型手册》——把你做过的题按"去重/排名/连续/同比/漏斗/留存"分类，每类留 2 道代表题 + 你的解法。

---

### 第 3–4 周：数据建模 + 数仓分层（约 60 小时）

**学什么**
1. **维度建模**（20h）
   - 事实表 vs 维度表、星型 vs 雪花、一致性维度
   - 三种事实表：事务型、周期快照、累积快照（举例：订单、库存日报、订单状态流转）
   - 缓慢变化维 SCD1/2/3（重点 SCD2：拉链表）
   - 代理键、退化维度、总线矩阵（能画出来就是加分）
2. **数仓分层**（16h）
   - ODS / DWD / DWS / ADS（+ DIM）各层职责、命名规范、数据流向
   - 为什么分层（复用、解耦、口径统一）、什么时候可以不分层
   - 指标体系：原子指标 / 派生指标 / 复合指标，口径文档怎么写
3. **建模实战**（16h）：拿电商订单场景，画 ER 图 + 星型模型 + 分层设计文档
4. **SQL 进阶练习**（8h）：用第 1–2 周的技能把这套模型的数据"造"出来（用 Python 生成 10 万行模拟数据）

**怎么学**：**每学一个概念，立刻在自己的项目里画一张图**。建模这东西看视频没用，必须自己画三遍。

**产出**：**项目 A 的设计文档**（ER 图、分层表清单、指标字典、每个表的字段与口径）——这份文档后来就是你面试时讲的"设计能力"。

---

### 第 5–6 周：Hive + Spark SQL（约 60 小时）

**学什么**
1. **Hive**（24h）
   - 架构（Metastore / HiveServer2 / 执行引擎）、内部表 vs 外部表、分区表 vs 分桶表
   - HiveQL 与 MySQL 的差异（`LATERAL VIEW explode`、`get_json_object`、日期函数）
   - 存储格式：Text / Parquet / ORC 的区别与选择
   - 常见坑：小文件问题、动态分区、数据倾斜
2. **Spark SQL**（24h）
   - RDD vs DataFrame、`spark-sql` 与 `pyspark` 两种写法
   - 读 Hive 表、写分区表、`repartition` vs `coalesce`
   - **Shuffle 是什么**、为什么慢、怎么减少
   - 数据倾斜的 3 种解法（加盐、广播小表、两阶段聚合）
3. **项目 A 实施**（12h）：把 ODS 层数据入 Hive，清洗成 DWD，做 DWS 汇总

**怎么学**：**先跑通一条链路（CSV → Hive 表 → SQL 汇总 → 结果表），再优化**。别一上来就学调优，先让数据流起来。

**产出**：项目 A 的 ODS/DWD/DWS 三层跑通，能 `SELECT` 出正确结果。

---

### 第 7–8 周：调度 + 数据质量 + OLAP + 看板（约 60 小时）

**学什么**
1. **调度**（16h）：DolphinScheduler（Docker 一键起）
   - 建项目、定义工作流 DAG、任务依赖、定时、补数、失败重跑、告警
   - 把项目 A 的每一层做成一个 DAG 节点
2. **数据质量**（12h）
   - 四类校验：非空、唯一、值域、波动（今天比昨天掉 50% 要报警）
   - 用 SQL 写校验任务 + 调度里挂"质量检查"节点
   - 数据血缘的基本概念（表从哪来、到哪去）
3. **OLAP 引擎**（16h）：Doris 或 ClickHouse 二选一（推荐 **Doris**，MySQL 协议、好上手）
   - 建表（明细模型/聚合模型）、导入数据、点查与聚合查询
   - 什么场景用 OLAP 而不是 Hive（低延迟、高并发看板）
4. **看板**（16h）：Superset 或 Metabase（Docker 起），连 Doris/MySQL 出 3–5 张图

**产出**：**项目 A 完整闭环**——采集 → ODS → DWD → DWS → ADS → Doris → 看板，全程由 DolphinScheduler 定时跑。

---

### 第 9–10 周：实时链路（Kafka + Flink）（约 60 小时）

**学什么**
1. **Kafka**（20h）：Topic/Partition/Offset、生产者与消费者、消费组、消息顺序与幂等、`acks` 语义
2. **Flink**（28h）
   - 流处理基本概念：事件时间 vs 处理时间、**Watermark**、窗口（滚动/滑动/会话）
   - `DataStream` API 与 **Flink SQL**（优先学 Flink SQL，更快出成果）
   - **Checkpoint 与状态**（背下来：干什么用的、怎么配）
   - 精确一次（exactly-once）的含义与实现前提
3. **项目 B**（12h）：模拟订单流 → Kafka → Flink SQL 实时聚合（每分钟 GMV / UV）→ 写入 Doris/MySQL → 看板刷新

**怎么学**：先用 Flink SQL 写一个"5 分钟滚动窗口统计"，跑通再学 Watermark 细节。**Flink 的坑在环境和状态，不在语法。**

**产出**：项目 B 跑通，能演示"数据进来 10 秒内看板数字变化"。

---

### 第 11–12 周：面试冲刺（约 60 小时）

**学什么**
1. **SQL 手写题**（20h）：牛客 SQL 60 题二刷 + 高频场景默写（留存、漏斗、连续登录、同比环比、TopN）
2. **数仓理论八股**（16h）
   - 为什么要分层？ODS 到 DWD 做了什么？
   - 星型 vs 雪花怎么选？拉链表怎么实现（`start_date/end_date/is_current`）？
   - 数据倾斜怎么发现、怎么解决？小文件怎么处理？
   - 全量 vs 增量、事实表的三种类型、指标口径冲突怎么办
3. **组件原理**（12h）
   - Hive：内部表/外部表区别、分区/分桶、Metastore 作用
   - Spark：Shuffle 原理、宽窄依赖、为什么比 MapReduce 快
   - Flink：Watermark、Checkpoint、窗口、状态后端
   - Kafka：为什么快（顺序写+零拷贝）、如何保证不丢不重
4. **项目讲述**（8h）：两个项目各准备 30 秒 / 3 分钟 / 10 分钟三个版本，每个准备 3 个"最难的点"
5. **投递**（4h）：BOSS 助手按"数据开发/大数据开发/ETL/数仓"关键词跑，优先中小公司

**产出**：《数据开发面试题库 + 我的答案》60 题 + 两个项目的讲稿。

## 六、项目 A 详细设计（**这是你简历的核心**）

**选题：深圳技术岗招聘数据数仓**（数据你自己用爬虫或公开数据集造）

> 选这个题的理由：① 数据你自己能造，不依赖别人 ② 场景贴深圳 ③ 你还能顺手用它指导求职

**分层设计**

| 层 | 表 | 说明 |
|---|---|---|
| ODS | `ods_job_raw` | 原始 JD（标题、公司、薪资、城市、技能标签、发布时间），按天分区 |
| DWD | `dwd_job_detail` | 清洗后：薪资拆成 min/max/月数、城市标准化、技能标签炸开成多行 |
| DIM | `dim_company` / `dim_city` / `dim_skill` | 维度表，SCD2 记录公司规模变化 |
| DWS | `dws_city_skill_daily` | 城市 × 技能 × 天：岗位数、平均薪资 |
| ADS | `ads_salary_rank` / `ads_skill_trend` | 薪资排行、技能热度趋势，供看板 |

**必须做到的 5 件事**（面试时讲这些）
1. 用 Python 生成/爬取 **≥5 万条** 模拟或真实 JD，落到 MySQL/CSV
2. 用 Hive 建分区表，**DataX 或 Python 脚本** 同步到 ODS
3. DWD 层做**薪资解析 + 技能标签 explode**（这是真实业务里最脏的活）
4. DWS 层用窗口函数算**同比/环比**
5. DolphinScheduler 串成 DAG，每天 2:00 跑；加 3 个质量校验节点（非空、唯一、环比波动 <30%）

**README 要写**：架构图、表清单、指标口径、调度截图、3 张看板截图、遇到的问题（数据倾斜/小文件/时区）及解法。

## 七、项目 B 详细设计（加分项）

**选题：实时订单指标**

## 十、怎么学才不白学

1. **SQL 是手感，不是知识**：每天 3 道，雷打不动。断三天就手生。
2. **建模必须画图**：学完一章，合上书自己画一遍，画不出就是没懂。
3. **组件先跑通再研究原理**：装 Hive 卡 3 天是新手通病，跑通一条最小链路比研究架构重要。
4. **每个报错都抄进笔记**：数据开发的坑 80% 是环境和小文件，抄多了自然不踩。
5. **项目要有数字**："5 万条数据、4 层、12 张表、调度每天 2:00 跑、单任务 90 秒"——这些数字比技术名词值钱。
6. **用 AI 当 SQL 教练**：写完 SQL 让它 review 有没有更优写法、能不能用窗口函数替代子查询。

## 十二、几个坑，提前说

1. **别一上来就学 Flink**：离线都没搞明白，学实时只会两头空。第 9 周再碰。
2. **别追求"完整 Hadoop 集群"**：单机 + Docker 足够面试，运维不是你的岗位职责。
3. **别只看视频**：数据开发是手艺，看十遍不如自己写一遍 SQL。
4. **别忽略业务口径**：面试官最爱问"这个指标你怎么算的、为什么这么算"，答不出就露怯。
5. **别等学完再投**：第 6 周（Hive 跑通、项目 A 有雏形）就可以开始投，面试反馈比自学有用。
