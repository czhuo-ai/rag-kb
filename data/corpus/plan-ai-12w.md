# 学习计划：AI 应用开发方向 · 12 周

> 目标：6 个月内具备投「AI 应用开发 / 大模型应用工程师 / LLM 工程师 / AI Agent 开发（1 年左右经验）」的能力，深圳为主。
> 你的起点：数据科学与大数据技术本科（2026 届）、会 Java + Spring Boot、会一点 Python、有 SQL 基础。
> 时间假设：**每天 4–6 小时、每周 6 天**，12 周 ≈ 390 小时。每天 2–3 小时就把周数 × 1.8。

---

## 一、先把"AI 相关的工作"分层看清楚

"做 AI"这四个字下面，其实是四种完全不同的岗位，门槛差 10 倍：

| 层级 | 岗位名 | 干什么 | 学历门槛 | 你能否够到 |
|---|---|---|---|---|
| **算法层** | 算法工程师（CV/NLP/推荐）、大模型训练 | 训练/微调模型、发论文 | **硕士起，卡论文** | ❌ 基本不可能 |
| **工程层** | 大模型推理优化、训练平台、分布式训练 | 让模型跑得快、跑得省 | 本科可，但要 C++/CUDA/系统功底 | ⚠️ 太难，不建议 |
| **应用层** ⭐ | **AI 应用开发 / LLM 工程师 / Agent 开发** | 用现成模型+工具搭出能用的产品：RAG、Agent、工作流 | **本科可，看项目** | ✅ **你的主战场** |
| **产品/运营层** | AI 产品经理、AI 运营 | 定义需求、做增长 | 本科可 | ⚠️ 非技术路线 |

**关键结论：你能碰、且 2026 年最缺人的，是「应用层」。**

这个岗位不要求你训模型，要求你：
- 知道某个模型能干什么、不能干什么
- 能把文档、数据库、API 变成模型能用的"上下文"
- 能把一次问答做成**稳定、可评测、成本可控**的服务
- 能说清楚"为什么这里用 RAG 不用微调"

**这就是工程能力，不是科研能力。** 你现有的 Java/Spring Boot 经历在这里直接用得上（写服务、设计接口、部署），Python 只是换把工具。

## 二、AI 应用层的四条细分路线

| 细分 | 典型岗位 | 核心技能 | 深圳需求 | 建议 |
|---|---|---|---|---|
| **RAG / 知识库** | AI 应用开发 | 文档解析、切分、向量检索、rerank、评测 | 最多 | ⭐ **主线** |
| **Agent / 工作流** | Agent 开发、LLM 工程师 | 工具调用、规划、多步执行、MCP | 增长最快 | ⭐ **主线** |
| **AI + 数据** | AI 数据工程、数据智能 | 数据管道、向量化、评测集构建、数仓 | 中 | ⭐ 你的差异化 |
| **AI 模型工程** | 推理优化、部署 | vLLM、量化、并发 | 少且门槛高 | 了解即可 |
| 微调 | —— | LoRA/SFT/DPO | 极少给应届 | 懂概念，做一个实验就够 |

**推荐组合：RAG + Agent 为主线，AI 数据工程做差异化标签。**
理由：你专业是数据科学，会 SQL 会数据清洗——"我既能把数据喂给模型，也能把模型做成产品"这句话，在面试里非常有辨识度。

## 四、环境与工具（第 0 周搞定）

- **Python**：3.11+，用 `uv`（比 pip 快 10 倍）或 conda 建虚拟环境
- **模型 API**：至少两家（DeepSeek / 智谱 / 通义 / 硅基流动），都要能跑通流式输出
- **本地模型**：Ollama（`ollama run qwen2.5:7b`），用于不花钱的调试
- **向量库**：PostgreSQL + `pgvector`（Docker 一行起），够用且面试好讲
- **框架**：`LangChain` / `LlamaIndex` / `LangGraph` 三选一先学（推荐 LangGraph，Agent 场景更清晰）
- **前端**：Streamlit 或 Gradio（半天就能做出能演示的界面，别在界面上花时间）
- **Docker**：所有服务容器化，面试时能说"一条 compose 起全套"

## 五、12 周主计划

### 第 0 周：Python 工程化 + 环境（约 25 小时）

**学什么**
- Python 补强（10h）：类型注解、`dataclass`、生成器、`asyncio` 基础、异常处理、虚拟环境
- FastAPI（8h）：路由、Pydantic 模型、依赖注入、异步接口、SSE 流式返回
- Docker（4h）：写 `Dockerfile`、`docker-compose` 起 postgres+pgvector
- 工具链（3h）：`uv`、`ruff`、`pytest` 基础、`.env` 管密钥

**产出**：一个能跑的 FastAPI 服务（`/health` + 一个调模型的 `/chat` 流式接口），Docker 里起得来。

---

### 第 1–2 周：LLM 应用基础（约 60 小时）

**学什么**
1. **模型基础认知**（8h）：token 与计费、上下文窗口、温度/top_p、模型能力边界（什么问它会瞎编）
2. **Prompt 工程**（16h）：角色设定、Few-shot、思维链、输出格式约束、Prompt 模板管理与版本
3. **结构化输出**（12h）：JSON Schema 约束、Pydantic 校验、失败重试、修复策略
4. **Function Calling / Tool Use**（16h）：工具定义、参数校验、多轮调用、错误处理
5. **流式与并发**（8h）：SSE、异步并发请求、超时与重试、限流

**怎么学**：每个点都要落到代码——**不要只调 API 看它回一句话**，要写出"能稳定产出结构化结果"的函数。

**产出**：一个「简历筛选助手」小工具：输入 JD + 简历，输出结构化匹配评分（JSON），带重试与校验。

---

### 第 3–4 周：RAG 上篇——把文档变成可检索的知识（约 60 小时）

**学什么**
1. **文档解析**（14h）：PDF（含扫描件 OCR）、Word、Excel、网页、Markdown；表格与图片怎么处理
2. **切分策略**（12h）：固定长度 vs 语义切分 vs 按标题层级；chunk size / overlap 怎么定；父子块
3. **Embedding**（12h）：`bge-m3` / `text-embedding-3` 等模型选型、维度、归一化、相似度度量（cosine vs 内积）
4. **向量库**（14h）：pgvector 建表与索引（HNSW/IVFFlat）、批量写入、元数据过滤、增量更新
5. **基础检索**（8h）：top-k、阈值、去重

**产出**：能把自己的一批文档（比如 100 篇技术文章/公司制度）入库，并用一句问句检索出正确的 3 段。

---

### 第 5–6 周：RAG 下篇——让它答得准（约 60 小时）★ 面试核心

**学什么**
1. **混合检索**（14h）：BM25 关键词 + 向量语义，怎么融合（RRF）、什么时候必须用关键词
2. **Rerank**（10h）：cross-encoder 重排（bge-reranker）、召回 20 条重排取 5 条
3. **上下文组装**（10h）：加引用编号、控制 token 预算、冲突信息处理
4. **幻觉与拒答**（10h）：无答案时怎么拒答、引用溯源、"不知道"的设计
5. **评测**（16h）：构建 100 条评测集（问题+标准答案+相关文档）、指标（命中率/召回@k/答案正确率）、LLM-as-judge、A/B 对比两版切分策略

**产出**：**项目 A 完成**（见下）。

---

### 第 7–8 周：Agent（约 60 小时）

**学什么**
1. **Agent 基础**（14h）：ReAct 循环、工具注册、观察结果、终止条件、最大步数
2. **多工具编排**（14h）：数据库查询、HTTP API、文件读写、代码执行（沙箱）
3. **规划与反思**（12h）：任务拆解、失败重试、自我检查、Human-in-the-loop
4. **MCP（Model Context Protocol）**（10h，2026 年的加分项）：协议概念、写一个自己的 MCP Server
5. **LangGraph / 工作流**（10h）：状态机、条件分支、持久化

**产出**：**项目 B 完成**（见下）。

---

### 第 9–10 周：部署、性能与成本（约 60 小时）

**学什么**
1. **本地推理**（14h）：Ollama 跑 7B 模型、vLLM 部署（PagedAttention 概念）、量化（INT8/INT4）对效果的影响
2. **性能**（14h）：并发压测（locust）、首 token 延迟 vs 总时长、流式体验
3. **成本**（12h）：token 计费拆解、缓存（精确缓存 + 语义缓存）、小模型分流（简单问题走小模型）、批处理
4. **可观测**（10h）：调用链日志、token 用量统计、错误率、告警
5. **微调认知**（10h）：了解 LoRA/QLoRA、SFT 数据构造、什么时候该微调（答案：RAG 解决不了格式/风格时才考虑）；做一个 30 分钟的小实验即可

**产出**：项目 A/B 全部 Docker 化，带一份《性能与成本报告》（QPS、P95 延迟、单次问答成本）。

---

### 第 11–12 周：面试冲刺（约 60 小时）

**学什么**
1. **AI 应用八股**（20h）
   - Transformer / Attention 的直觉解释（不用推公式，但要能讲清 QKV）
   - tokenizer 原理、上下文窗口与截断策略
   - RAG 各环节的取舍：切分大小怎么定？为什么用 rerank？混合检索解决什么问题？
   - 幻觉的成因与四类缓解手段
   - Function Calling 的原理（本质是让模型输出结构化 JSON）
   - Agent 为什么会"绕圈"、怎么限制
   - 评测怎么做、LLM-as-judge 的偏差
   - 什么时候用 RAG、什么时候微调、什么时候都不行
2. **工程题**（16h）：高并发下的限流、缓存策略、超时重试、幂等、长文本怎么分段处理
3. **项目讲述**（12h）：两个项目各 30 秒 / 3 分钟 / 10 分钟三版；每个准备 3 个"最难的点"
4. **投递**（12h）：BOSS 助手加关键词「AI应用 / 大模型 / LLM / RAG / Agent / 算法工程师(应用)」；优先 AI 创业公司 + 中大厂的 AI 应用团队

**产出**：《AI 应用面试题库》50 题 + 两个项目讲稿 + 一份作品集网页（可选）。

## 六、项目 A：企业知识库问答（RAG 全链路）

**目标**：给一个"公司内部文档"做问答，答得准、有引用、不会瞎编。

**技术栈**：FastAPI + pgvector + bge-m3 + bge-reranker + DeepSeek/Qwen API + Streamlit

**必须做到的 8 件事**（这就是面试能讲 10 分钟的内容）
1. 支持 PDF/Word/Markdown 三种格式，扫描件走 OCR
2. 三种切分策略各跑一遍，用评测集比较（**这是最能体现工程思维的一步**）
3. 混合检索：BM25 + 向量，RRF 融合
4. Rerank：召回 20 条 → 重排取 5 条
5. 回答必须带 `[1][2]` 引用，能点开看原文
6. 无答案时拒答（阈值 + 二次校验），不许编
7. 100 条评测集，输出命中率 / 召回@5 / 答案正确率，并对比"改前 vs 改后"
8. Docker Compose 一键起（postgres + api + ui）

**README 要写**：架构图、评测报告表格、成本估算（每次问答多少 token、多少钱）、踩过的坑（PDF 表格解析、chunk 太小导致答不全）。

## 七、项目 B：数据分析 Agent（结合你的数据背景）⭐

**目标**：自然语言问数据 → Agent 自己生成 SQL → 查库 → 画图 → 用中文解释。

**技术栈**：FastAPI + LangGraph + MySQL/DuckDB + 一个开源 BI 库出图 + LLM

**必须做到的 6 件事**
1. 工具集：`list_tables` / `get_schema` / `run_sql` / `plot` / `explain`
2. SQL 安全：只允许 SELECT、加 LIMIT、超时、白名单表
3. 错误自愈：SQL 报错 → 把错误喂回模型 → 重写（最多 3 次）
4. 多步：先看表结构 → 再写 SQL → 再校验结果是否合理 → 最后解释
5. 前端：一句话提问 → 出表 + 出图 + 结论
6. 评测：50 个自然语言问题 + 期望结果，统计"SQL 一次通过率"

**为什么这个项目值钱**：它同时证明三件事——你会数据（SQL/建模）、会 Agent（工具编排）、会把 AI 做成产品。深圳做数据智能的公司很吃这套。

## 十、怎么学才不白学

1. **先跑通一条最短链路**：文档 → 切分 → 向量 → 检索 → 拼 prompt → 回答。**两小时就能跑通，别一上来就追求完美架构。**
2. **每个技术选型都问"为什么不用另一个"**：为什么 pgvector 不用 Milvus？为什么 bge 不用 OpenAI？答不出说明你在抄教程。
3. **评测集是护城河**：会做评测的人比会调 API 的人少 10 倍，面试时一提"我建了 100 条评测集"立刻区分度拉满。
4. **不要迷信框架**：LangChain 只是胶水，先把 HTTP 调模型 + 自己拼 prompt 写一遍，再用框架。
5. **成本意识**：每次实验记 token 花费，面试问"你这个项目一个月多少钱"你能答出来就是加分。
6. **用 AI 学 AI**：让模型解释论文、review 你的 prompt、生成评测数据——但每个结论自己验证一遍。

## 十二、几个坑，提前说

1. **别去啃 Transformer 论文**：你能讲清 Attention 的直觉就够了，面试官不会让应用岗推公式。
2. **别做"聊天机器人"当项目**：那是 2023 年的项目，现在人人都有。要有 RAG、有评测、有工程。
3. **别只用一个模型**：面试会问"模型挂了怎么办""怎么在效果和成本间取舍"。
4. **别忽略传统工程**：并发、缓存、限流、日志——AI 应用首先是"应用"。
5. **别等学完再投**：第 6 周（项目 A 有雏形）就开投，AI 岗位面试问得非常具体，反馈极有价值。
6. **岗位关键词要多试**：AI 应用开发 / 大模型应用 / LLM 工程师 / Agent 开发 / 算法工程师（应用）/ AI 产品研发，同一个岗位在不同公司叫法完全不同。
