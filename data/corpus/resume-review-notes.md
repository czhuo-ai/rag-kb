# 简历诊断：现在这版的问题，以及改了什么

看完你这份简历（2 页，2025-12 版），先说结论：

> **这是一份「诚实的课程作业简历」。它能过 HR 的关键词筛选，但过不了技术面的第一眼。**
> 不是内容少，是**没有告诉对方"你能解决什么问题、做到了什么程度"**。

---

## 一、7 个具体问题

**1. 定位和目标岗不匹配（最致命）**
你写「求职意向：Java 开发工程师」，但两个项目都是教学级 CRUD（图书管理、宿舍电量）。深圳 Java 应届岗一天收几百份这种简历，HR 和面试官都看腻了。
👉 改法：不换项目，换**讲法**——把「我实现了 CRUD」改成「我解决了什么业务问题、用什么技术、达到什么指标」。

**2. 量化只有两个数字**
「<100ms」「500+ 宿舍」很好，但只出现一次。其余全是「实现了…」「完成了…」「具备了…」。
👉 改法：每条 bullet 至少带一个数字（接口数、表数、QPS、耗时、数据量）。没有真实数字的，就写清「覆盖什么场景、替代了什么人工流程」。

**3. 「了解」用得太多**
了解 Redis、了解 Vue、了解 Linux、了解 LangChain4J——**招聘方看到「了解」就默认为「不会」**。
👉 改法：分三级写——会用的写「熟练/独立完成」，摸过的单独列在「了解」后面一小行，别和主力技能混在一起。

**4. 没有 GitHub、没有能跑的东西**
后端岗位最看重「代码在哪」。你写了两个系统，但对方无法验证。
👉 改法：今天就把两个项目传 GitHub（README 写清怎么跑），简历第一行放链接。这是**性价比最高的一步**。

**5. 教育背景时间写错**
「2022-09 〜 至今」——你是 2026 届，要写「2022.09 – 2026.06（预计）」，否则 HR 判断不了你是哪届。
👉 同理「到岗时间：随时到岗」应该写「2026 年 6 月毕业，可提前实习」。

**6. 期望薪资写「面议」**
应届生写面议，等于把定价权交给对方，还显得没底。
👉 改法：写区间（深圳本科 Java 应届：8–12K），面试时再谈。

**7. 模板痕迹和自我评价**
「细心从每一个细节开始 / Personal resume」这种模板标语要删；自我评价 4 行全是形容词，和技能栏重复。
👉 改法：自我评价压到 3 条，每条一个**可验证的事实**。

## 二、改完的结构变化

| 原来 | 现在 |
|---|---|
| 两页，信息密度低 | 一页（A4），HR 8 秒能看完 |
| 技能 6 段「了解…」 | 5 行分级技能，主力在前 |
| 项目按「主要职责 1/2/3/4」平铺 6 条 | 每条项目：背景 → 我做的 → 结果，3 条以内 |
| 没有量化 | 每个项目至少 2 个数字 |
| 无 GitHub | 首屏链接 |
| 求职意向单一 | 后端为主，数据开发并列（你的专业是数据科学，这是加分项） |

## 三、你现在最该做的 3 件事（按性价比排序）

1. **传 GitHub**（1 小时）：两个项目 + README + 运行截图。简历立刻从"我说我会"变成"你可以看"。
2. **补一个"数据"项目**（1–2 周）：你的专业是数据科学与大数据技术，但现在简历里一个数据相关的东西都没有——这是最大的浪费。做一个「深圳 Java 岗位爬取 + 薪资/技能词频分析」，技术栈 pandas + requests + MySQL + 一个看板。**它同时能投数据开发和后端两个方向**。
3. **背 3 个问题的答案**（半天）：
   - 你的项目里最难的技术点是什么，怎么解决的？
   - 为什么用 MyBatis-Plus 而不是 JPA？
   - 索引为什么会失效？你项目里怎么验证的？

## 四、如果你也想投「数据 / 运营」方向

你这份简历的底子是**后端 + 数据科学专业**，转「数据型运营」几乎无缝：

- 宿舍电量系统 → 「独立完成业务数据建模，设计 4 表结构支撑 500+ 主体数据管理」
