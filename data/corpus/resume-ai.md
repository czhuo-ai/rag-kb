## 项目经历

### 企业知识库问答系统（个人项目）

`FastAPI · pgvector · bge-m3 · bge-reranker · DeepSeek API · Streamlit · Docker Compose`

- **背景**：企业文档分散在 PDF、Word、网页中，人工查找一份制度文件平均需【X】分钟；通用大模型直接作答无依据、无法定位原文。
- **文档处理**：实现 PDF（含扫描件 OCR）、Word、Markdown 三类解析；对比固定长度、语义、标题层级三种切分，基于 100 条标注问题选定配置（chunk 512 / overlap 64）。
- **检索**：pgvector（HNSW）建立索引，支持文档类型过滤与增量入库；BM25 与向量双路召回，RRF 融合取前 20 条，再经 bge-reranker 重排取前 5 条，命中率【A】% 提升至【B】%。
- **回答与引用**：回答要求带 [1][2] 引用角标并可跳转原文；最高相似度低于阈值时返回「未找到依据」，无依据作答比例由【C】% 降至【D】%。
- **工程实现**：FastAPI + SSE 流式接口，Docker Compose 一键部署；单次问答成本【E】元，P95 首字延迟【F】ms。

### 自然语言数据分析 Agent（个人项目）

`LangGraph · FastAPI · MySQL · DuckDB · Plotly · DeepSeek API`

- **背景**：业务人员不具备 SQL 能力，取一个指标依赖数据岗排期，平均等待【X】小时；临时取数需求占用分析岗较多时间。
- **流程编排**：基于 LangGraph 实现五节点流程：读取表结构 → 生成 SQL → 执行 → 结果校验 → 绘图与文字说明；SQL 执行失败时将错误信息回传模型重写，最多重试 3 次。
- **安全控制**：仅允许 SELECT 语句，强制追加 LIMIT，限制可访问的表清单，查询超时 5 秒，避免误删与全表扫描。
- **图表与结论**：根据问题类型自动选择折线图、柱状图或饼图；文字结论仅基于本次查询结果生成，不引入结果之外的信息。
- **效果**：在 50 条自然语言问题的评测集上，SQL 首次执行成功率【A】%，端到端答案正确率【B】%，平均响应时间【C】秒。
- **稳定性**：对结果行数与数值量级做合理性校验，异常时重新生成 SQL，错误 SQL 的比例由【D】% 降至【E】%。
- **部署**：记录每一步的 token 消耗与耗时；提供 Docker 镜像，接入新数据库仅需配置连接串。
